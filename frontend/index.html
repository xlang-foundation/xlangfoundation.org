02 / The concept

Keep the computation
within reach.

Readable source and explicit execution boundaries give developers room to inspect, integrate, and specialize AI software.

A language designed for native applications.

XLang3 runs Python-compatible source through an explicit execution pipeline. Native applications can embed the runtime rather than treating every script as a separate process.

Read the XLang3 design ↗
# XLang3 execution pipeline source.py → parser → syntax tree → semantic model → program IR / graph IR → executors → native runtime

The model is a program.
The profile is its execution policy.

Garnet keeps model semantics separate from backend decisions. Profiles describe execution choices; the compiler captures, partitions, lowers, and specializes the model graph.

Explore the model workflow ↗
# Garnet compilation workflow xModel + Tensor Expressions → inspectable graph + backend / precision / shape profile → partition → lower → compile → hardware-specialized execution

One agent runtime.
Multiple ways to work.

xMind starts with an agent/tool loop. Add skills, named agents, or graphs when the task needs them. Its clients share native sessions and execution state, with embedded XLang3 for scripting.

Read the xMind architecture ↗
# xMind client and runtime architecture CLI / browser / VS Code → shared C++ backend → agents + tools + models → sessions + approvals + history → embedded XLang3 scripting

These diagrams explain project architecture, not a promise that every integration is complete. Model coverage, backends, and validation status are documented in the individual repositories.
