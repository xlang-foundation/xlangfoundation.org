THE LANGUAGE / WHAT YOU CAN BUILD ON

Python-compatible at the surface.
Native capabilities underneath.

XLang3 combines a general-purpose language, an embeddable runtime, and explicit computation and communication APIs. Explore the implementation behind each capability.

01 / LANGUAGE

Familiar programming constructs.

Functions, classes, decorators, generators, async workflows, imports, and Python-style data structures. Compatibility is tracked by behavior and tests, rather than implied by a familiar syntax.

Explore compatibility coverage ↗
02 / NATIVE INTEGRATION

Embed it. Extend it.

Use shared or static runtime builds. Integrate native packages through a C-compatible API and C++ helpers, keeping the application and script on the same native runtime.

Explore native extensions ↗
03 / TENSOR COMPUTATION

Graphs, with a CPU executor.

Capture symbolic tensor operations and run supported arithmetic, broadcasting, reductions, views, and batched matrix multiplication on the built-in CPU executor. No Garnet, NumPy, CUDA, or GPU is required for this path.

Explore tensor operations & tests ↗
04 / PROCESSES

Make native workers cooperate.

Shared-memory LRPC connects runtime instances and native C++ hosts. Remote objects, explicit serialization, cancellation, and process-lifetime handling support applications that span process boundaries.

Explore shared-memory IPC ↗
05 / CODE & STATE

Transfer more than plain data.

Serialize supported functions, closure cells, classes, instances, and object graphs while preserving aliases and cycles. Compatible receiving runtimes can restore code without the original script file.

Read the trusted-transfer contract ↗
06 / NATIVE MODULES

Connect to real application work.

The repository includes native modules for JSON, SQLite, networking, cryptography, compression, ctypes, and CFFI. Combine supported pure-Python packages with XLang3-native dependencies.

Explore the module source ↗
07 / DEVELOPER TOOLS

Inspect execution.

Run scripts and modules from the CLI, inspect compiled IR, and debug through the native DAP adapter. Trace hooks, frames, and monitoring support Python-oriented debugging integrations.

Explore debugging tools ↗
08 / LANGUAGE EXTENSIONS

Keep selected expressions symbolic.

Native packages can capture decorator arguments as expression values instead of evaluating them immediately. Inspect resource conditions and evaluate them against an explicit snapshot.

A SMALL EXAMPLE / REAL TENSOR API

From expression to execution.

Create symbolic inputs, compose a graph, then supply concrete values. This example uses XLang3's built-in CPU path. Backend runtimes can replay captured graphs into their own execution systems.

Read the full example and supported operations ↗
import tensor as T

x = T.input("x", shape=[2, 3])
bias = T.tensor([1, 2, 3])
graph = T.graph((x + bias) * T.unary_op("relu"))

result = graph.run({
    "x": T.tensor([[1, 2, 3], [4, 5, 6]])
})
XLANG3 / EXECUTION ARCHITECTURE

In-process when it fits.
Across processes when it scales.

Designed for high-performance native applications, cooperating worker services, and demanding workloads.

01 / EMBED

Native in-process execution.

Embed XLang3 in a native application and execute Python-compatible logic through its own runtime. CPython is not the execution engine.

Explore the runtime ↗
02 / CONCURRENCY

Designed without a CPython-style GIL.

The runtime design uses per-thread VM state, atomic object lifetimes, and explicit object-sharing rules rather than a CPython-style global interpreter lock.

Read the threading policy ↗
03 / IPC

Shared-memory communication.

Connect separate processes with shared-memory LRPC. Expose native C++ packages as remote objects and organize compute-heavy work into cooperating workers.

Read the IPC guide ↗

Performance depends on workload and synchronization. The threading policy records remaining legacy lock regions and an open synchronization audit; it does not claim every path is lock-free. Explore measured performance and validation →

A DEVELOPER STORY / FASTAPI ON XLANG3

The app stayed familiar.
The runtime changed.

A route. A request model. An async handler. A FastAPI application starts with familiar Python code. The interesting question is what happens when that source runs on a different execution engine.

01
Start with a familiar application.

The compatibility suite includes an end-to-end FastAPI and Pydantic example: routes, request models, and async handlers. Explore compatibility tests ↗

02
Change the execution engine.

Run supported FastAPI workflows through XLang3's native runtime, without CPython as the execution engine. Native integration connects application logic to C++ services. Read the native-host guide ↗

03
Grow beyond a single process.

Move heavy tasks into native workers and connect them through shared-memory IPC. Recovery, cancellation, and value lifetimes matter as much as the first successful remote call. Read the validation record ↗
